# MVP 요구사항과 결정

## 목표

첫 버전은 사용자가 앱을 열었을 때 프로젝트나 우선순위를 다시 선택하지 않고 실행 가능한 `NOW` 카드 한 장에서 바로 시작할 수 있어야 한다.

## 승인 조건

- 프로젝트의 완료 상태, 판단 기준, 기본 실행 시점·장소, 세션 길이를 저장할 수 있다.
- 이어받을 위치, 직전 결과, 첫 행동, 완료 조건, 검증 방법, 우회 행동을 가진 카드 사슬을 한 번에 만들 수 있다.
- 첫 실행 가능한 카드는 `NOW`, 나머지는 입력 순서대로 `NEXT`가 된다.
- 실행 화면에는 NOW 한 장만 표시한다.
- 완료 증거와 집중시간을 저장하면 현재 카드는 `DONE`, `NEXT` 첫 장은 `NOW`가 된다.
- 카드에 적힌 우회 행동도 불가능할 때 외부 의존 정보를 기록하고 `WAITING`으로 이동한다.
- WAITING 이동과 동시에 NEXT 첫 장을 NOW로 승격한다.
- WAITING 해소 시 NOW가 없으면 NOW, 있으면 NEXT 꼬리로 복귀한다.
- 새로고침 후 프로젝트, 카드 상태, 순서, 증거, 실행 기록이 복구된다.
- 시간 경과만으로 NOW나 순서를 변경하지 않는다.

## 전역 불변조건

```text
NOW     0..1장
NEXT    0..3장
WAITING 외부 답변·자료·피드백을 기다리는 카드
DONE    완료 증거와 완료 시각이 있는 카드
```

- NOW와 NEXT 상한은 프로젝트별이 아니라 시스템 전체에 적용한다.
- NEXT의 순서는 1부터 중복과 빈 번호 없이 이어진다.
- 완료·대기 전이와 NEXT 첫 카드 승격은 하나의 상태 갱신으로 처리한다.
- 프로젝트가 달라도 전역 NEXT 순서대로 승격한다.
- 완료 증거가 없으면 DONE 전이를 거부한다.
- 이전 카드 ID로 반복 전이를 요청해도 새 NOW에는 적용하지 않는다.

## 불명확했던 부분의 결정

### 막힘

`BLOCKED`를 영구 상태로 추가하지 않는다. 막힘은 NOW에서 카드의 우회 행동을 실행하는 사건이다. 사용자가 우회 행동도 불가능하다고 판정할 때만 WAITING으로 이동한다.

### 여러 프로젝트

프로젝트별 NOW를 만들면 사용자가 프로젝트를 다시 골라야 한다. 따라서 여러 프로젝트도 하나의 전역 실행 큐를 공유한다. `주력 1 + 유지 1`은 데이터 제약이 아니라 운영 지침으로 둔다.

### 카드 수

문서에는 주간 카드 3~5장과 `NOW 1 + NEXT 3`이 함께 적혀 있다. MVP 활성 사슬은 문서의 보드 상한을 우선하여 최대 4장으로 제한한다. 진행해 자리가 비면 후속 카드를 연결한다.

### 미완료

시간이 끝났지만 미완료인 경우 별도 상태를 추가하지 않는다. 사용자는 이어받을 위치, 직전 결과, 첫 행동, 완료 조건을 한 세션 크기로 갱신하고 같은 NOW를 유지한다.

### WAITING 복귀

현재 NOW를 빼앗지 않도록 NOW가 있으면 NEXT 꼬리로, 없으면 NOW로 보낸다. NEXT가 이미 3장이면 복귀를 거부하고 큐가 비워진 뒤 다시 시도하도록 안내한다.

## 기술 결정

GitHub Pages에서 빌드 없이 직접 서빙하기 위해 표준 Web Components와 ES Modules를 사용한다. 컴포넌트의 템플릿, 이벤트, scoped CSS는 한 파일에 함께 두며 Shadow DOM으로 스타일 범위를 격리한다. 도메인 규칙과 저장 모듈은 컴포넌트에서 분리해 UI 변경과 무관하게 테스트한다.
