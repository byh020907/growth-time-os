Growth Time OS

할 일 한 줄이 다음 행동까지 이어진다

역사 토론 원문

문서 상태: 현재 Product Desired State · 단일 제품 명세 원본

Growth Time OS는 일반 TodoList의 간단함을 유지하면서 가장 먼저 할 일과 다음 순서를 다시 고르는 부담을 없앤다. 할 일을 한 줄로 추가하면 첫 항목을 NOW로 보여 주고, 완료·계속·대기 중 하나를 선택하면 이미 정한 흐름을 그대로 이어 준다.

1. 제품 개요

매일 계획을 다시 세우는 생산성 시스템이 아니라, 이미 적은 Todo를 지금 행동으로 연결하는 강화된 개인 TodoList다.

사용자와 목표 경험

Target User

일반 TodoList의 간단함은 유지하면서 가장 먼저 할 일과 다음 순서를 다시 고르는 부담을 줄이고 싶은 개인 사용자.

Desired Outcome

사용자는 할 일을 한 줄로 추가하고 NOW 하나부터 처리한다. 완료, 계속 또는 대기만 선택하면 미리 입력한 다음 할 일이 자동으로 NOW가 된다.

Why “OS”

OS는 Operating System의 비유다. 거대한 운영체제를 만든다는 뜻이 아니라, 사용자가 매번 순서를 결정하지 않아도 Todo의 실행 상태와 다음 차례를 일관되게 운영한다는 의미다.

Example Boundary

설명에 필요한 구체적인 예시는 토익 학습만 사용한다. 제품의 상태와 흐름은 다른 자기계발 Todo에도 같은 규칙으로 적용된다.

일반 TodoList의 기본 문법과 Growth Time OS의 변화
일반 TodoList baseline 유지하는 경험 Growth Time OS Delta

기능 수로 일반 TodoList를 대체하지 않는다. 핵심 차이는 선택지를 늘리는 것이 아니라 시작 마찰과 다음 결정 하나를 없애는 데 있다.

2. 핵심 사용 흐름

  1. 한 줄 추가
    해야 할 일을 짧게 적는다. 첫 항목은 NOW, 이후 항목은 NEXT가 된다.
  2. NOW 실행
    앱을 열면 NOW 하나만 보고 바로 시작한다.
  3. 자동 이어가기
    완료·계속·대기 중 하나를 선택하면 다음 상태가 자동으로 준비된다.
  • 다시 고르지 않는다. 하루마다 프로젝트나 우선순위를 재선택하게 하지 않는다.
  • 놓쳐도 유지한다. 하루가 지나도 NOW와 사용자가 정한 순서는 그대로다.
  • 필요한 만큼만 묻는다. 기본은 제목 한 줄이며 상세 입력은 선택 사항이다.

3. Todo 상태와 실행 순서

전역 실행 순서를 구성하는 네 상태
상태수량의미
NOW0..1개지금 실행할 전역 Todo. 두 개 이상일 수 없다.
NEXT0..3개프로젝트와 관계없이 실행 순서가 이미 정해진 전역 대기열.
WAITING—외부 답변, 자료 또는 준비물을 기다리는 Todo.
DONE—완료 시각과 결과 표시가 남은 Todo.

처리한 NOW는 DONE 또는 WAITING으로 이동하고 NEXT 첫 항목이 NOW로 승격된다. 계속을 선택하면 같은 NOW를 유지한다.

PG-004 · Global Queue

프로젝트가 달라도 실행 순서는 하나다

  • 시스템 전체에서 NOW는 최대 하나, NEXT는 최대 세 개다.
  • 빈 목록에 만든 첫 Todo는 NOW, 나머지는 입력 순서대로 NEXT가 된다.
  • 기존 NOW가 있으면 새 Todo는 NEXT의 끝에 추가된다.
  • NEXT 순서는 사용자가 Todo 목록 화면에서만 미리 조정한다.

4. 빠른 추가와 NOW 집중

빠른 경로는 제목만 받는다. 실행을 이어 갈 정보가 정말 필요한 Todo만 자세히 작성한다.

PG-001 · Focus

앱을 열면 NOW 하나에 집중한다

  • 기본 실행 화면은 NOW Todo만 단독으로 보여 준다.
  • NOW에는 프로젝트, 제목, 예상 세션, 실행 시점과 장소가 표시된다.
  • NOW가 없으면 앱이 임의로 프로젝트를 고르지 않고 할 일 한 줄을 추가하도록 안내한다.
  • NEXT나 다른 프로젝트를 고르는 control은 실행 화면에 노출하지 않는다.

PG-002 · Quick Capture

할 일은 제목 한 줄만으로 추가한다

  • 기본 추가 flow에는 Todo 제목 한 필드와 추가 action만 보여 준다.
  • Enter로 저장하며 공백 제목은 입력을 잃지 않고 같은 자리에서 거부한다.
  • 프로젝트가 없어도 첫 Todo를 추가할 수 있고 내부 기본 목록이 자동으로 준비된다.
  • 첫 Todo는 NOW, 이후 Todo는 NEXT 끝에 즉시 나타난다.
  • 프로젝트, 위치, 완료 조건 같은 상세 정보는 자세히를 선택한 경우에만 질문 하나씩 작성한다.

PG-003 · Optional Detail

빠른 Todo는 기본값으로 실행하고 필요할 때만 구체화한다

  • 빠른 Todo의 첫 행동은 제목 자체이며 완료 여부는 사용자가 직접 판정한다.
  • 빠른 Todo에는 새 할 일, 별도 위치 없음, 직접 완료 확인과 같은 안전한 내부 기본값을 사용한다.
  • 빠른 Todo의 자동 생성 상세값은 기본 NOW 화면에서 노출하지 않는다.
  • 상세 Todo는 이어받을 위치, 직전 결과, 첫 행동, 완료 조건, 검증 방법과 우회 행동을 작성할 수 있다.
  • 기존 상세 Todo와 그 기록은 그대로 유지되고 실행할 수 있다.

5. 완료·계속·대기

NOW에서 필요한 판단은 세 가지뿐이다. 완료하면 닫고, 계속하면 자리를 유지하고, 막히면 기다리는 대상을 남긴 뒤 다음 Todo로 이동한다.

PG-005 · Complete

빠른 Todo는 한 번 눌러 완료하고 자동으로 이어 간다

  • 빠른 Todo는 추가 입력 없이 완료할 수 있다.
  • 빠른 완료에는 시스템이 완료 표시를 증거로 남긴다.
  • 상세 Todo는 필요한 경우 완료 증거와 실제 집중시간을 입력한다.
  • 완료 Todo는 DONE으로 이동하고 NEXT 첫 항목이 같은 처리에서 NOW가 된다.
  • 이미 처리한 Todo의 반복 동작은 새 NOW에 적용되지 않는다.

PG-007 · Miss and Continue

놓친 날을 벌주지 않고 같은 NOW를 계속한다

  • 시간 경과나 하루 누락만으로 NOW, NEXT 순서 또는 날짜를 바꾸지 않는다.
  • 빠른 Todo의 다음에 계속은 추가 입력 없이 같은 NOW를 유지하고 새 실행 기회를 준비한다.
  • 상세 Todo는 필요할 때 남은 일을 한 세션 크기로 다시 적는다.
  • 미완료 인계는 이전 실행을 닫고 다음 실행 기회를 새로 준비한다.
  • 놓친 시간을 보충하도록 여러 Todo를 한꺼번에 강요하지 않는다.

PG-006 · Block and Wait

대기는 한 줄만 남기고 다음 Todo로 넘어간다

  • 빠른 Todo는 기다리는 대상을 한 줄로 적어 WAITING으로 보낸다.
  • 상세 Todo는 우회 행동, 막힌 이유와 선택적인 확인 날짜를 추가로 기록할 수 있다.
  • WAITING 전환과 NEXT 첫 Todo 승격은 함께 일어난다.
  • 대기 해제 시 NOW가 없으면 NOW, 있으면 NEXT 끝으로 돌아오며 NEXT가 가득 차면 명확히 거부한다.

6. 보존·검토·접근

PG-008 · Persistence

같은 기기에서 실행 맥락을 보존한다

  • 프로젝트, Todo 상태와 순서, 완료 표시와 실행 기록은 같은 browser와 device에서 다시 열어도 유지된다.
  • 저장 실패는 성공처럼 보이지 않고 현재 입력을 유지한 text error로 알린다.
  • 손상된 저장 data는 앱을 중단시키거나 잘못된 NOW를 만들지 않고 안전한 빈 상태로 복구한다.

PG-009 · Evidence Review

최근 실행을 증거로 검토한다

  • 최근 7일 실행 기회 대비 시작률을 보여 준다.
  • 완료 산출물 수, 집중시간과 WAITING 전환 수를 보여 준다.
  • 완료 Todo의 프로젝트, 제목, 완료일과 표시를 확인할 수 있다.
  • 오래 유지된 NOW도 최근에 시작하거나 종료했다면 최근 기록에 포함한다.

PG-010 · Access

설치 없이 모바일과 데스크톱에서 실행한다

  • current desktop/mobile browser에서 핵심 loop를 수행할 수 있다.
  • 화면과 control은 text label 또는 accessible name으로 목적을 식별할 수 있다.
  • keyboard focus가 보이며 주요 작성과 실행 동작을 keyboard로 수행할 수 있다.
  • 좁은 화면에서 horizontal scroll 없이 핵심 action과 내용을 사용할 수 있다.

PG-011 · Mobile Install and Update

홈 화면에 설치하고 새 version을 안전하게 적용한다

  • 지원하는 mobile/desktop browser는 Growth Time OS의 이름, icon, theme와 standalone 실행 정보를 인식한다.
  • browser가 설치 prompt를 제공하고 아직 설치되지 않은 경우에만 사용자가 실행할 수 있는 설치 action을 보여 준다.
  • 설치한 앱은 NOW를 시작점으로 별도 app window에서 열리고 기존 local project와 Todo를 그대로 사용한다.
  • 새 app version이 준비되면 작업을 강제로 중단하거나 자동 reload하지 않고 update 안내와 업데이트·나중에 선택을 보여 준다.
  • 사용자가 update를 선택하면 새 version으로 한 번 reload하고 durable local data를 유지한다.
  • 설치나 update 확인이 지원되지 않거나 실패해도 기존 NOW loop는 계속 동작한다.

8. 확정 원칙과 제외 범위

항상 지키는 원칙

  • 계정 생성, 설치와 network connection 없이 핵심 loop를 사용할 수 있다.
  • 사용자 실행 data는 명시적인 외부 기능이 생기기 전까지 해당 browser/device를 떠나지 않는다.
  • 알림, 연속 출석과 보상 장치보다 시작 마찰과 선택지 제거를 우선한다.
  • 사용자 확인 없이 프로젝트 방향이나 Todo 순서를 자동 변경하지 않는다.
  • 기본 Todo 추가에서 제목 외 입력을 요구하지 않는다.

포함하지 않는 시스템

  • cloud account, multi-device sync와 협업
  • 소셜 feed, 경쟁 ranking과 streak badge
  • 복잡한 calendar 최적화와 과도한 notification
  • 여러 생산성 도구를 한 번에 대체하는 범용 suite
  • AI가 확인 없이 목표나 우선순위를 바꾸는 동작
  • native app package와 app store 배포
  • push notification과 background user-data sync
